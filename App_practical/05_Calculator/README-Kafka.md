# Лабораторная 3: Kafka

Код подготовлен локально. Ничего не отправлено в GitHub или на учебный сервер.

## Поток данных

Форма → Kafka (kunev-5-calculations) → KafkaConsumerService → HTTP Callback → MariaDB.
Страница опрашивает результаты каждые две секунды. Offset подтверждается после
успешного Callback. Доставка как минимум однократная: при сбое после сохранения,
но до подтверждения offset возможна повторная запись.

## Локальная проверка

1. Из папки с Compose выполнить `docker compose up -d mariadb kafka kafka-ui`.
2. В Visual Studio открыть консоль диспетчера пакетов и выполнить `Update-Database`.
   Development-настройки используют localhost:5335 и базу 5-WebCalculatorDb.
   Эта команда нужна для новой пустой локальной БД; к учебному серверу она не обращается.
3. Запустить проект в Visual Studio. Открыть http://localhost:5005/.
4. Выполнить несколько расчётов, дождаться строк в таблице.
5. В http://localhost:10015/ открыть Topics → kunev-5-calculations → Messages.
6. В HeidiSQL (localhost:5335, root/password) проверить DataInputVariants.

Для запуска веб-приложения в Docker после подготовки схемы остановить запуск
из Visual Studio и выполнить `docker compose up -d --build web`.

## Существующая БД второй лабораторной

Числа и операции в C# преобразуются EF Core в прежние varchar(128):
операции записываются именами Add/Subtract/Multiply/Divide. Старые миграции
сохранены; изменение типов столбцов и удаление старой БД не нужны.
Прежние числовые строки должны содержать корректные числа; ошибочные записи
потребуют отдельной проверки.

## Перед будущим запуском на учебном сервере

Этот Compose создаёт отдельный проект kunev-lab3 с собственными томами.
Он не подключает автоматически старый контейнер второй лабораторной.
Порты 5005 и 5335 могут быть уже заняты второй лабораторной: запускать на сервере
без согласования со старым развёртыванием нельзя. Это ещё не выполнено.

Внутри Docker используются mariadb:3306 и kafka:9092; из Visual Studio —
localhost:5335 и localhost:9095. Если запуск из Visual Studio должен обращаться
к учебному серверу, необходимо отдельно изменить Development-настройки и задать
KAFKA_EXTERNAL_HOST на сервере. Сейчас настроен только локальный вариант.

Приложение не применяет миграции автоматически и не создаёт БД при старте.
